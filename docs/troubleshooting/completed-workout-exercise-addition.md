# Completed workout exercise addition troubleshooting

| Symptom                                                        | Likely cause and diagnostics                                                                       | Resolution                                                                                                                        |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| An active workout gained an exercise through completed history | The addition reached an active session, or the completed status was not checked.                   | The use case refuses anything that is not completed, and `correctCompleted` checks the stored status again.                       |
| Completed addition appears on the active workout screen        | The active screen reached the history use cases.                                                   | Addition lives only in `workout-history`; the active screen keeps its own `addExercise` and nothing else.                         |
| An exercise appeared without anybody adding it                 | Something other than the addition path wrote children.                                             | No catalog edit, plan change, preference, migration, or background task may write here; find the other writer.                    |
| A completed workout holds an exercise that recorded nothing    | The exercise was written before its first set, or the set was built separately.                    | The exercise is only ever constructed holding exactly one set; a two-step write is the defect.                                    |
| The added exercise is not last                                 | The position came from something other than the loaded exercise count.                             | Append at `stored.exercises.length`; `WorkoutSession.create` rejects any other value.                                             |
| An existing exercise changed position or identifier            | The rebuild reconstructed existing exercises from values instead of spreading the loaded ones.     | Spread the loaded aggregate and append; assert existing rows unchanged row-for-row in a real-database test.                       |
| An existing captured snapshot changed                          | The Catalog was read for an exercise history already holds.                                        | The Catalog is read only for the definition being added; no existing snapshot may be re-read or revalidated.                      |
| The added exercise carries the wrong name                      | The definition was renamed after the workout, or a snapshot was copied from an earlier occurrence. | Expected for a rename: the snapshot is captured at the moment of addition. Never guess a historical name from earlier history.    |
| `UNIQUE(workout_session_id, position)` failed mid-write        | Rows were inserted without deleting the existing children first.                                   | `correctCompleted` deletes every child before inserting any; a targeted insert bypasses that ordering.                            |
| The parent row or a lifecycle instant changed                  | The write reached `replace` rather than `correctCompleted`.                                        | `correctCompleted` has no parent statement; `replace` keeps its single active-session caller.                                     |
| Orphaned `workout_set` rows appear                             | Children were left to `ON DELETE CASCADE` inside the transaction, where foreign keys are off.      | Delete sets, then exercises, explicitly, then reinsert everything; assert the orphan count in a test.                             |
| A failed addition left the exercise without its set            | Writes ran outside the exclusive transaction.                                                      | One `runExclusive` per addition; a throw must roll back both rows.                                                                |
| Another workout changed                                        | A statement was not bound to the selected session.                                                 | Every statement takes the session identifier; assert the other workout row-for-row in a test.                                     |
| An old screen added an exercise to a newer workout             | The loaded lifecycle instants were not compared against storage.                                   | Send the loaded start and completion instants and refuse as `changed` when they no longer match.                                  |
| Saving twice added two exercises                               | The in-flight guard was missing or reset before navigation.                                        | An addition is not idempotent: guard the call, disable the control while a write is in flight, and leave the screen on success.   |
| The addition was refused as invalid values                     | The recorded result does not match the definition's logging mode.                                  | `WorkoutSessionExercise.create` enforces compatibility; the form is driven by the selected definition's mode.                     |
| A full workout offers a control that does nothing              | The blocked case was expressed by disabling instead of by words.                                   | Render the fixed sentence in place of the control at `workoutSessionPolicy.maximumExercises`.                                     |
| The addition asked for a destructive confirmation              | The removal's alert was copied.                                                                    | Addition destroys nothing; it saves explicitly with an explanatory card, as adding a missing set already does.                    |
| A deleted definition still added an exercise                   | The Catalog read happened outside the transaction, or its result was not checked.                  | Read the definition inside the transaction and refuse as `definition-not-found` when it is gone.                                  |
| The screen navigated somewhere other than the detail           | The addition reused the deletion's navigation.                                                     | The workout still exists; return to the detail and let it refresh in place.                                                       |
| The completed workout count or elapsed time changed            | The parent row was touched, or a second workout was recorded instead.                              | Only children change here; the count and elapsed time come from parent rows.                                                      |
| Progress or a personal record did not follow an addition       | A screen did not reload, or something derived was persisted.                                       | Nothing derived is stored; reopen the screen so the reader recomputes from the new facts.                                         |
| The occurrence appears under today's date                      | A reader used the addition time rather than the workout's captured date.                           | Per-exercise history reads `started_local_calendar_date` from the parent row; no addition timestamp exists.                       |
| The added exercise is missing from a new export                | The export ran against a stale read or a cached page.                                              | Export reads current rows; recreate the export after the addition commits.                                                        |
| A restored export dropped the added exercise                   | That file was created before the addition.                                                         | Expected. Addition changes local data only and never reaches a saved file; say so rather than implying otherwise.                 |
| The Exercise Library gained or lost a definition               | The addition wrote catalog rows.                                                                   | Addition reads one definition and writes none; creating definitions from completed history is out of scope.                       |
| A failure message names an exercise, a value, or a date        | An error was built from data rather than from the refusal reason.                                  | Map each refusal to its fixed sentence in `completed-exercise-addition-messages.ts`.                                              |
| The interface claims the application knows the work happened   | Wording drifted from the person's claim to the product's knowledge.                                | Say "record what you performed"; never restore, recover, sync, or fix.                                                            |
| Maestro cannot find the exercise in the picker                 | The picker lists recently performed exercises first once a completed workout exists.               | Search by name rather than expecting the whole catalog; the fallback to `listAll` applies only while no completed workout exists. |
| Maestro cannot find the addition entry point                   | It sits below the exercise list, which grows with the workout.                                     | `scrollUntilVisible` with `centerElement: true` before tapping.                                                                   |
| A Maestro tap on save lands on a number key                    | The iOS number pad covers the save control on the set form.                                        | Dismiss with a short drag, then scroll to the control before tapping.                                                             |
