# Workout personal records troubleshooting

| Symptom                                                   | Likely cause and diagnostics                                                                                       | Resolution                                                                                                     |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| No records after finishing a workout                      | The session is still active, or it completed without an actual set. Check lifecycle state without logging records. | Finish a workout with at least one recorded set. Planner intent never counts.                                  |
| A record counts a planned target                          | A projection reached the `planned_*` columns on the exercise row.                                                  | Restrict every branch to `workout_set` result columns and add a regression test.                               |
| A record is larger than any single set                    | The query summed a session instead of comparing sets.                                                              | Compare one set per row; totals belong to the performed-session summary.                                       |
| Loaded and unloaded results share one record              | Category identity dropped the captured logging mode.                                                               | Partition by `logging_mode_snapshot`; only the two unloaded repetition modes merge.                            |
| An assisted record credits the largest assistance         | The branch ordered descending, so the heaviest assistance won.                                                     | `least-assistance` orders ascending; the direction comes from its descriptor, never from the builder.          |
| An assisted record claims something about repetitions     | A second dimension was added to the assisted category.                                                             | The category claims assistance only; combining it with repetitions would be the score this design refuses.     |
| An assisted exercise still shows the old refusal sentence | The screen kept a mode-specific branch that is no longer true.                                                     | Only the generic undescribed-mode sentence remains, and it is reached through the read model, not a mode name. |
| Zero assistance cannot be recorded                        | `workout_set.resistance_grams` is constrained above zero, by design.                                               | An unassisted repetition is a different logging mode with its own record group. Never relax the constraint.    |
| A record shows as zero                                    | A missing dimension was defaulted instead of omitted.                                                              | Absence is absence; every recorded quantity is strictly positive by invariant.                                 |
| The record date moved after an equal result               | Tie ordering preferred the latest occurrence.                                                                      | Ties resolve to the earliest completed occurrence; verify the full total order.                                |
| A record changed after switching units                    | A converted value entered the comparison.                                                                          | Compare canonical grams, seconds, millimetres, and repetitions; convert only for display.                      |
| A record changed after a timezone change                  | Grouping used the current zone rather than the captured local date.                                                | Use the captured `started_local_calendar_date`; history is never regrouped.                                    |
| A renamed exercise rewrote old record cards               | The screen used the current name for every occurrence.                                                             | Headings use the latest snapshot; a card uses the name captured at its occurrence.                             |
| A deleted exercise disappeared from the list              | The exercise list resolved identifiers through the Exercise Catalog.                                               | Derive the list from completed snapshots; only the session picker resolves the Catalog.                        |
| Records are slow on a long history                        | An unbounded scan or a JavaScript maximum was introduced.                                                          | Keep one `LIMIT 1` branch per category and confirm the source history index in the query plan.                 |
| Records fail but history renders                          | The record statement raised a safe persistence failure.                                                            | Use the section retry; diagnose without exposing identifiers, names, dates, or values.                         |
| Stale records appear after navigating quickly             | A superseded response was rendered.                                                                                | Discard responses from earlier requests; the screen reloads on focus.                                          |
| Records survive local erasure                             | A derived value was cached or persisted somewhere.                                                                 | Nothing derived may be stored; recompute from history on every read.                                           |
