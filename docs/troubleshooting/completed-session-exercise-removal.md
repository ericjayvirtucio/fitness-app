# Completed session exercise removal troubleshooting

| Symptom                                                       | Likely cause and diagnostics                                                                      | Resolution                                                                                                                   |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| An active workout lost an exercise through completed history  | The removal reached an active session, or the completed status was not checked.                   | The use case refuses anything that is not completed, and `correctCompleted` checks the stored status again.                  |
| Completed removal appears on the active workout screen        | The active screen reached the history use cases.                                                  | Removal lives only in `workout-history`; the active screen keeps its own `removeExercise` and nothing else.                  |
| An exercise disappeared without anybody removing it           | Something other than the removal path rewrote children.                                           | No catalog edit, plan change, preference, migration, or background task may write here; find the other writer.               |
| A completed workout was left with no recorded set             | The emptying check ran after the rebuild, or not at all.                                          | Count the recorded sets of the survivors before writing anything and refuse as `would-empty-workout`.                        |
| The refusal shows as a control that does nothing              | The blocked case was expressed by disabling instead of by words.                                  | Render the fixed sentence in place of the control and point at deleting the whole workout.                                   |
| Surviving exercises hold a position gap                       | The survivors were written without renumbering.                                                   | Rebuild each survivor at its index; `WorkoutSession.create` rejects a gap, so a gap means the rebuild was bypassed.          |
| `UNIQUE(workout_session_id, position)` failed mid-write       | Positions were updated in place instead of rewritten.                                             | Delete every child before inserting any; the existing order never holds two rows at one position.                            |
| A surviving exercise or set changed identifier                | The survivors were reconstructed from values rather than spread from the loaded aggregate.        | Spread the loaded exercise and keep its sets; assert identifiers row-for-row in a real-database test.                        |
| A captured snapshot changed                                   | The rebuild passed new snapshot values instead of carrying the loaded ones.                       | Only `position` may differ; compare the survivor row to its previous row in a test.                                          |
| The parent row or a lifecycle instant changed                 | The write reached `replace` rather than `correctCompleted`.                                       | `correctCompleted` has no parent statement; `replace` keeps its single active-session caller.                                |
| Orphaned `workout_set` rows appear                            | The children were left to `ON DELETE CASCADE` inside the transaction, where foreign keys are off. | Delete sets, then exercises, explicitly, then reinsert the survivors; assert the orphan count in a test.                     |
| A failed removal left half a workout                          | Writes ran outside the exclusive transaction.                                                     | One `runExclusive` per removal; a throw must roll the whole thing back.                                                      |
| Another workout changed                                       | A statement was not bound to the selected session.                                                | Every statement takes the session identifier; assert the other workout row-for-row in a test.                                |
| An old screen removed an exercise from a newer workout        | The loaded lifecycle instants were not compared against storage.                                  | Send the loaded start and completion instants and refuse as `changed` when they no longer match.                             |
| Removing twice raised an error                                | The second attempt was treated as a failure rather than as nothing to do.                         | An exercise that is already gone is a refusal that reads as no longer part of the workout; disable the control in flight.    |
| The confirmation states a stale recorded set count            | Another screen corrected a set after this one loaded.                                             | Accepted: the target is the exercise identifier, so only the count can be stale. Reopen the detail to see the current count. |
| The screen navigated away after a removal                     | The removal reused the deletion's navigation.                                                     | The workout still exists; refresh the detail in place and announce the result politely.                                      |
| The completed workout count changed                           | The parent row was touched, or a whole workout was deleted instead.                               | Only children change here; the count comes from parent rows.                                                                 |
| Progress or a personal record did not follow a removal        | A screen did not reload, or something derived was persisted.                                      | Nothing derived is stored; reopen the screen so the reader recomputes from the remaining facts.                              |
| A per-exercise occurrence or performed exercise stayed listed | The reader counted exercises without requiring an actual set.                                     | Those readers join or `EXISTS` on `workout_set`; a removed exercise has no set left to join.                                 |
| A removed exercise is still in a new export                   | The export ran against a stale read or a cached page.                                             | Export reads current rows; recreate the export after the removal commits.                                                    |
| A restored export brought the exercise back                   | That file was created before the removal.                                                         | Expected. Removal changes local data only and never reaches a saved file; say so rather than implying otherwise.             |
| The Exercise Library lost or regained a definition            | The removal touched catalog rows.                                                                 | Removal is confined to the session aggregate; history reads snapshots and recreates nothing.                                 |
| A failure message names an exercise, a value, or a date       | An error was built from data rather than from the refusal reason.                                 | Map each refusal to its fixed sentence in `completed-exercise-removal-messages.ts`.                                          |
| The interface offers undo or recovery                         | Wording was added without any stored copy.                                                        | No undo, trash, audit, or tombstone exists; remove the claim rather than inventing the data.                                 |
| An empty exercise vanished on its own                         | Something cleaned up after a correction.                                                          | An exercise that recorded nothing stays until somebody removes it deliberately; automatic cleanup is a silent removal.       |
| Maestro cannot find the removal control                       | Two exercises share a captured name, or the control is below the fold.                            | The label carries the displayed position; scroll with `centerElement: true` before tapping.                                  |
| The Maestro alert tap hits the title instead of the button    | The title and the destructive action share their words.                                           | Tap the exact button text and let full-match semantics separate it from the title.                                           |
